# P5N-B - GraphBuilder Extraction Results

Date: 2026-04-30

## Summary

P5N-B extracted graph construction into a narrow header-only `GraphBuilder` module while keeping `AudioEngine::buildGraphFromModelLocked` as the compatibility wrapper.

No DSP, dry/wet, routing behavior, RuntimeGraphManager, command semantics, graph lifecycle ownership, parameter IDs, preset schema, golden baselines, or known failures were changed.

## Files Modified

- `Source/Core/Audio/GraphRuntimeTypes.h` (new)
- `Source/Core/Audio/GraphBuilder.h` (new)
- `Source/Core/AudioEngine.h`
- `Source/Core/AudioEngine.cpp`
- `docs/p5n-b-graphbuilder-extraction-results.md` (new)

Validation artifacts were regenerated by the required scripts.

## Types Created / Moved

Moved from private `AudioEngine` state into `Nova::Audio` runtime types:

- `GraphChainNodeSpec`
- `GraphRuntimeSlot`
- `GraphRuntime`

Created build boundary types:

- `GraphBuildRequest`
- `GraphBuildResult`
- `GraphBuildWarning`

`AudioEngine` keeps compatibility aliases:

- `using ChainNodeSpec = Nova::Audio::GraphChainNodeSpec`
- `using ChainRuntimeSlot = Nova::Audio::GraphRuntimeSlot`
- `using GraphRuntime = Nova::Audio::GraphRuntime`

## Module Created

- `Source/Core/Audio/GraphBuilder.h`
  - Header-only to avoid `NOVA.jucer` churn.
  - Does not include `AudioEngine.h`.
  - Owns one-shot control-plane graph construction from `GraphBuildRequest`.

## Logic Moved

Moved from `AudioEngine::buildGraphFromModelLocked` into `GraphBuilder::build`:

- graph allocation and play-config setup
- IO node creation
- `InputChainProcessor`, `ChannelStripProcessor` A/B, and `OutputChainProcessor` creation
- global processor raw-pointer caching
- telemetry tag assignment:
  - `channel-strip-a`
  - `channel-strip-b`
  - `output-chain`
- input routing, including mono input duplication to input-chain channel 1
- model chain slot construction for Line A / Line B
- `PedalRegistry::createPedal` factory behavior
- failed pedal/node skip behavior
- `ProcessorBase*` and `TempoSyncable*` cache population
- initial bypass application
- stable zone-order chain connection
- strip-to-output and output-to-IO graph connections
- initial runtime params application before prepare/rebuild
- `graph.prepareToPlay(...)`
- `graph.rebuild()`
- latency capture after rebuild with `MAX_GRAPH_LATENCY_SAMPLES` clamp

Moved runtime-param application body into:

- `GraphBuilder::applyRuntimeParamsToGraph(...)`

`AudioEngine::applyRuntimeParamsToGraph(...)` remains as a wrapper so existing control paths keep the same call sites.

## What Stayed In AudioEngine

- `publishGraph`
- `RuntimeGraphManager`
- graph lifecycle ownership and retired cleanup
- command queue/applier semantics
- model mutation
- `flushPendingGraphCommands`
- `applyPedalBypassToActiveGraph`
- dry/wet processing and latency compensation buffers
- routing/dry-wet process path
- health monitor, CPU meter, tuner
- diagnostics report collection/format delegation

`AudioEngine::buildGraphFromModelLocked(...)` now gathers the same current state into `GraphBuildRequest`, calls `GraphBuilder`, and returns the built runtime.

## Behavior Preservation

### Topology

`GraphBuilder` constructs the same graph shape:

- input IO -> `InputChainProcessor`
- input chain -> Line A chain -> strip A
- input chain -> Line B chain -> strip B
- strip A/B -> `OutputChainProcessor`
- output chain -> output IO

No dry/wet or runtime graph ownership code was moved.

### Zone Order

The `Pre -> Amp -> FX -> Cabinet -> unknown` ranking moved with the connection helper and still uses `std::stable_sort`, preserving equal-zone insertion order and unknown-last behavior.

### Runtime Params Application Order

Initial runtime params are still applied before:

1. `graph.prepareToPlay(...)`
2. `graph.rebuild()`
3. latency capture

Subsequent param updates still call `AudioEngine::applyRuntimeParamsToGraph(...)`, which delegates to the same builder helper.

### Prepare / Rebuild / Latency Capture

The order remains:

1. build nodes/connections
2. apply runtime params
3. `prepareToPlay(sampleRate, blockSize)`
4. `rebuild()`
5. capture `graph.getLatencySamples()`
6. clamp to `Nova::Config::MAX_GRAPH_LATENCY_SAMPLES`

### ProcessorBase / TempoSyncable Caches

The dynamic casts remain control-plane graph-build work only. Runtime slots still cache:

- `ProcessorBase*`
- `TempoSyncable*`

`AudioEngine::process` does not perform these casts.

### Failure Skip Behavior

Failed pedal creation and failed graph node insertion still:

- log `engine.addPedal.failed`
- skip the slot
- keep graph build non-fatal

The log message content is preserved for the two existing failure cases.

## Remaining Risks

- `GraphBuilder` is header-only and includes several construction dependencies; a future `.cpp` split may be cleaner if this module grows.
- `AudioEngine::buildGraphFromModelLocked` still runs under the same current model-lock context. This preserves behavior, but later lock-scope reduction should be a separate phase with explicit validation.
- Graph build warnings are currently logged immediately by `GraphBuilder`; `GraphBuildWarning` is available but not yet consumed by `AudioEngine`.

## Recommendation For P5O

Keep P5O conservative:

1. Add direct GraphBuilder unit coverage only if it can avoid broad public internals.
2. Consider moving `GraphBuilder` to `.cpp` only with proper `NOVA.jucer` update/re-export.
3. Do not reduce model-lock scope or change build failure handling in the same phase as any further topology work.
4. Re-run the full P5N validation matrix after any GraphBuilder follow-up.
