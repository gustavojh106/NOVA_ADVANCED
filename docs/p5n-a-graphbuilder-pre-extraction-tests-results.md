## Tests Added

1. `AudioEngine mixed-zone insertion keeps zone-canonical effective routing`
- **Risk covered:** zone order drift and effective routing drift.
- **What it checks:** mixed insertion order (including unknown zone) stays behaviorally equivalent to canonical zone insertion (`Pre -> Amp -> FX -> Cabinet -> unknown`) using finite-output checks, latency equality, and low null-RMS comparison.

2. `AudioEngine mixed-chain latency stays stable across equivalent rebuilds`
- **Risk covered:** latency drift across rebuild paths.
- **What it checks:** stable latency across disable/enable rebuild and clear+rebuild equivalent chain; bypass/unbypass latency invariants on latency-relevant chain; finite output after rebuilds.

3. `AudioEngine global processor path responds after prepare with no pedals`
- **Risk covered:** missing or broken global processor path after build.
- **What it checks:** no-pedal path remains finite, LineA/LineB pedal node counts stay zero, input gain path changes output magnitude, limiter telemetry reports active limiting when driven, active graph remains published in diagnostics.

4. `AudioEngine known ProcessorBase and TempoSyncable pedals remain stable`
- **Risk covered:** cache/path regressions for ProcessorBase and tempo-sync context delivery.
- **What it checks:** bypass/unbypass keeps same active processor instance for known pedal, Delay receives host tempo context (bpm/valid/transport), finite output under the chain.

5. `AudioEngine tempo-sync context variants remain stable on Delay`
- **Risk covered:** tempo context propagation edge regressions.
- **What it checks:** multiple host-tempo validity/transport combinations propagate to Delay runtime state deterministically.

## What Could Not Be Covered Directly (and Why)

1. **Direct graph connection edge-level introspection** (exact node-to-node wiring)
- Not exposed as stable public API; forcing this would require opening internals and increase refactor risk.
- Behavioral equivalence checks (null-RMS + latency + finite output) were used instead.

2. **Direct proof of “no dynamic_cast in audio callback path” from test code**
- This is better enforced by policy scan/contracts than by fragile unit-test instrumentation.
- `check-audio-thread-policy.ps1` contract checks remain PASS (`contractFailures=0`).
